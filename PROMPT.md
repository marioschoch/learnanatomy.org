# Build Prompt — Open Anatomy Atlas (Z-Anatomy based)

> How to use: put this file in the root of an empty project folder, start Claude Code there, and say:
> **"Read PROMPT.md and execute it, starting with Phase 0."**

---

## 0. Role and goal

You are the **lead engineer and orchestrator** for a new open-source, nonprofit web app: an interactive 3D anatomy atlas for medical students. Students can view the human body as overlapping, toggleable layers (bones, joints, muscles, vessels, nerves, organs, skin, …). They can make layers transparent, cut through the body along anatomical planes, explode regions apart, search for and isolate structures, read their names and definitions, and quiz themselves.

You coordinate a small team of subagents (described in Phase 1). You own the architecture, the shared contracts, the integration and the final quality. Work in phases. **Stop after Phase 0 and wait for my approval before writing feature code.**

Working name of the project: **Open Anatomy Atlas** (I may rename it later; keep the name in one config constant).

## 1. Context and hard constraints

- **Nonprofit, free to use, no accounts, no backend, no tracking/analytics** in v1. It is a static site.
- **Data source: Z-Anatomy** (derived from BodyParts3D). License: **CC BY-SA 4.0**. Some upstream components carry **non-commercial** licenses (e.g. the inner ear model is CC BY-NC-SA 4.0, a kidney model is CC BY-NC 4.0). Definitions come from Wikipedia (CC BY-SA 3.0), partly machine-translated. Consequences:
  - All processed 3D assets and extracted metadata are published under **CC BY-SA 4.0** with full attribution.
  - Application code is **MIT** (separate license file). Keep code and assets clearly separated.
  - Every structure keeps its license/attribution in metadata; NC-licensed structures get `nonCommercial: true` so they can be removed with a single filter if the project ever changes.
  - Definitions are shown with an "unreviewed source" badge until a human reviewer marks them reviewed.
- **Audience:** medical students (desktop and tablet first, phone must work). UI languages: **German and English**. Anatomical names: **Latin (Terminologia Anatomica) and English**, plus German only where the source data provides it. **Never machine-translate anatomical names or invent anatomy facts.**
- **Correctness beats features.** A swapped left/right or a mislabeled structure is a critical bug.

Check the current API of three.js (BatchedMesh in particular), drei and gltf-transform against the installed versions. Don't rely on memory.

### Contract sketch (adapt to the real data)

```ts
export type Lang = 'la' | 'en' | 'de' | string;
export type Side = 'left' | 'right' | 'midline' | 'bilateral';

export interface Manifest {
  schemaVersion: 1;
  generatedAt: string;
  source: { name: 'Z-Anatomy'; url: string; license: 'CC BY-SA 4.0' };
  languages: Lang[];                 // languages actually present in the data
  units: 'm';                        // normalized: body ≈ 1.75 m tall, feet at y=0, centered on x/z, facing +z
  systems: SystemInfo[];
  regions: RegionInfo[];
  searchIndexFile: string;           // small file loaded at startup
}

export interface SystemInfo {
  id: string;                        // e.g. 'skeletal', 'muscular', 'cardiovascular'
  names: Record<Lang, string>;
  color: string;                     // hex, from source materials
  layerOrder: number;                // 0 = innermost (skeleton) … highest = skin
  defaultVisible: boolean;
  defaultOpacity: number;            // 0..1
  chunks: { file: string; bytes: number; region?: string }[]; // split if > 20 MB
  structuresFile: string;
  structureCount: number;
  triangleCount: number;
}

export interface RegionInfo { id: string; names: Record<Lang, string>; }

export interface Structure {
  id: string;                        // stable, URL-safe slug, unique
  nodeName: string;                  // node name inside the GLB chunk
  chunk: string;
  system: string;
  regions: string[];
  side?: Side;
  pairId?: string;                   // left/right counterpart
  parentId?: string;                 // for the hierarchy tree (groups)
  names: Record<Lang, string>;       // at least la or en
  synonyms?: string[];
  taId?: string; fmaId?: string;
  definition?: { text: Partial<Record<Lang, string>>; source: string; license: string; reviewed: boolean };
  centroid: [number, number, number];
  bbox: { min: [number, number, number]; max: [number, number, number] };
  labelAnchor?: [number, number, number];
  triangles: number;
  license: string;
  attribution: string;
  nonCommercial?: boolean;
}

export interface SearchEntry { id: string; system: string; names: Record<Lang, string>; synonyms?: string[]; }
```

## 6. Phase 1 — Parallel work with subagents

After my "go", spawn **three subagents in parallel** using the Agent/Task tool. Give each one its brief below (verbatim), the contract files and `ARCHITECTURE.md`. Each works only in its owned directories, runs its own verification and returns a short report: what it built, what it verified and how, open issues, and proposed contract changes. **Do not mark an agent's work as done until you have reviewed its diff yourself.**

### Agent A — Asset Pipeline (`pipeline/`)

Goal: turn the Z-Anatomy .blend into web-ready, compressed, validated assets + metadata.

1. `blender/export.py` (headless):
   - For each anatomical system collection (as found in the inventory), export only MESH objects. Skip text, curves, leader lines and helpers. **Do** record label/annotation object positions as `labelAnchor` for the structure they belong to.
   - Apply modifiers, triangulate, Y-up glTF export (`export_format='GLB'`, `export_apply=True`, `export_yup=True`, `export_extras=True`). Node name = stable structure id. Keep base color only, no textures.
   - Normalize: units to meters, body height ≈ 1.75 m, feet at y = 0, centered on x/z, body facing +z.
   - Extract per-structure metadata: names in every available language, TA/FMA ids if present, side, hierarchy/parent group, regions, definition text + source, centroid, bbox, triangle count, license, NC flag.
   - **Deliver the skeletal system first, as early as possible**, so Agent B can switch from mocks to real data.
2. `process.mjs` (gltf-transform): dedup, weld, prune, careful simplify (thin structures like nerves/vessels must survive; start with a very low error threshold and report the triangle reduction per system), quantize, EXT_meshopt_compression. If a system chunk exceeds 20 MB, split it by region.
3. `manifest.mjs`: write `public/models/manifest.json`, `structures/<system>.json` and a compact `search-index.json` (names + synonyms only). Generate `ATTRIBUTION.md` with the exact upstream attributions from the Z-Anatomy README, a modification note, and a list of NC-licensed structures.
4. `validate.mjs` (fails with a non-zero exit code on errors):
   - every structure has exactly one GLB node and vice versa; ids unique and URL-safe; every structure has at least an `la` or `en` name
   - file sizes under the limit; total size and triangles per system reported
   - **orientation sanity checks:** the liver centroid is on the patient's right, the heart apex/spleen/stomach are on the patient's left, the head is up, the face points toward +z, and `.l`/`.r` structures are on the correct side. Any failure is a critical error.
5. Report a stats table: systems, structures, triangles before/after, bytes per file, languages present, % of structures with definitions, # NC structures.

Verify: `npm run assets:build` runs end-to-end from a clean `public/models/`, and `assets:validate` passes.

### Agent B — 3D Viewer Core (`src/viewer/`)

Goal: a fast, correct, beautiful 3D viewer driven entirely by the store. Develop against mocks first, then real assets.

1. **Loading:** load the manifest and search index at startup; load system chunks lazily when a system is first made visible (default: skeletal + one more as defined in the manifest). Show progress per system. Use the meshopt decoder.
2. **Rendering strategy:** one **BatchedMesh per system** (or per chunk), built from the GLB geometries, with a map `batchId ↔ structureId`. Per-structure visibility via `setVisibleAt`, highlight via `setColorAt`, exploded positions via `setMatrixAt`. If BatchedMesh hits a blocker, document it and fall back to merged geometry with a per-vertex structure-id attribute + GPU picking. Keep draw calls ≈ number of visible systems.
3. **Layers and X-ray:** per-system visibility and opacity (0–100 %). Opaque systems render first. Transparent systems use `depthWrite=false`, are ordered by `layerOrder` (inner → outer), and use a depth pre-pass per transparent system to avoid self-overlap artifacts. Enable BatchedMesh per-instance sorting if available. Test visually that skin at 20 % over muscles at 60 % over opaque bones looks clean.
4. **Picking:** hover highlight (desktop only, throttled) and click/tap to select, using three-mesh-bvh or GPU picking. Clicks on invisible or fully transparent (< 5 %) systems are ignored. Dragging the camera must not trigger a selection.
5. **Selection and isolate:** selected structure gets a clear highlight (tint + optional outline). "Isolate" hides everything except the selection; "isolate with context" renders all other systems ghosted (~8 % opacity, desaturated). Exiting isolate restores the previous state exactly.
6. **Clipping / cross-sections:** three anatomical planes — **sagittal, coronal, transverse** — each toggleable, with a position slider and a flip button, applied to all materials (`localClippingEnabled`). Cut surfaces must not look hollow: render back faces in a flat "cut" color (via `gl_FrontFacing` in the shader). Proper stencil capping is a stretch goal.
7. **Exploded view:** a slider 0 → 1. Each structure moves away from the center of its region/system along (centroid − center), smoothly animated. It works together with selection and picking (raycasts must hit the moved positions).
8. **Camera:** CameraControls with damping; "focus on selection" (fit bbox, animated); reset; **standard anatomical views** (anterior, posterior, left lateral, right lateral, superior, inferior); an orientation gizmo labelled with **A/P, L/R (patient's), S/I**. Zoom limits so you can't fly inside forever.
9. **Labels:** labels for the selected structure and pinned structures (drei `Html` + leader line to `labelAnchor` or the nearest surface point). Labels avoid overlapping where feasible and hide when their structure is hidden or clipped away.
10. **Utilities:** screenshot (PNG of the canvas), `frameloop="demand"` with invalidation, adaptive DPR, touch gestures on mobile, and a lightweight dev-only stats overlay (fps, draw calls, triangles from `renderer.info`).

Verify: unit tests for the pure logic (explode math, clipping state, id maps); a Playwright smoke test that loads the mock scene, selects a structure via a test hook and takes a screenshot; `typecheck` and `lint` are clean.

### Agent C — UI, Search, Learning (`src/ui/`, `src/quiz/`, `src/i18n/`)

Goal: a clean, fast, student-friendly interface. Talk to the viewer only through the store/viewer API. Develop against mocks.

1. **Layout:** desktop — left sidebar (Layers + Structure tree tabs), right info panel, top search bar, bottom toolbar (views, X-ray, clipping, explode, isolate, screenshot, help). Tablet — collapsible panels. Phone — bottom sheets, and the 3D view stays usable. Light and dark theme.
2. **Layers panel:** each system shows a color chip, a visibility toggle, an opacity slider and a loading indicator. Presets: "Skeleton", "Bones + Muscles", "Circulation", "Nervous system", "Organs", "Full X-ray", "Reset".
3. **Structure tree:** system → group → structure, virtualized (thousands of rows), with a visibility checkbox per node (including groups), a filter box, and click-to-select/focus. It stays in sync with the selection (scrolls to it).
4. **Search:** Fuse.js over all names, languages and synonyms. Results appear while typing with keyboard navigation (↑↓ Enter Esc) and show the system chip and the side (L/R). Selecting a result loads the system if needed, then selects and focuses the structure. `/` or `Ctrl/Cmd+K` focuses search.
5. **Info panel:** shows the names (Latin bold, then English/German), system, region(s), side, a link to the counterpart (left ↔ right), and the definition with source + "unreviewed" badge + license note. Actions: Focus, Isolate, Isolate with context, Hide, Pin label, "Quiz me on this region".
6. **Name language toggle:** display names in Latin / English / German (fall back to Latin → English when missing; never translate). The UI language (DE/EN) is a separate toggle and defaults to the browser language.
7. **Quiz mode** (`src/quiz/`):
   - Scope picker: systems, regions, side (L/R/both), number of questions.
   - Question types: **Locate** ("Click the …" → the user clicks in 3D; feedback highlights the correct one), **Identify** (a structure is highlighted → 4 options, with distractors from the same system and region), **Name it** (type the Latin/English name, with fuzzy acceptance and a typo tolerance shown in the feedback).
   - Score, a review of mistakes at the end, and a "retry mistakes" option.
   - Simple spaced repetition (Leitner boxes) stored in localStorage per structure, wrapped in try/catch. "Practice weak structures" mode.
   - During the quiz, labels and the info panel are hidden so they don't give away answers.
8. **URL state:** selection, visible systems + opacities, clipping, explode, camera view, and name language are encoded in the URL (compact) so a link reproduces the view. Teachers can share links.
9. **Help overlay** (controls, shortcuts), **About/Credits page** (project purpose, nonprofit, full attribution from `ATTRIBUTION.md`, code/asset licenses, "educational use only — not for diagnosis"), and a first-visit hint.
10. **Accessibility:** keyboard reachable controls, focus rings, ARIA labels, sufficient contrast, reduced-motion respected (no animated camera flights).

Verify: unit tests for search ranking, quiz generation (no duplicate options, distractors from the right scope), Leitner logic and URL encode/decode round-trip; component tests for key panels; `typecheck` and `lint` are clean.

## 9. Performance budgets

- Startup download before the first interactive view: **≤ 5 MB** (manifest + search index + skeletal system, compressed).
- Time to first interactive view on a decent laptop over a normal connection: **≤ 3 s**; skeleton visible ≤ 4 s.
- Orbiting with all systems visible: **≥ 50 fps** on a modern laptop, **≥ 30 fps** on a mid-range phone with the default layers.
- Draw calls in the default view: **≤ 30**.
- No single file > 20 MB; the main JS bundle ≤ 400 kB gzip (code-split the quiz and credits).
- Memory: no geometry leaks when toggling systems repeatedly (check `renderer.info.memory`).
